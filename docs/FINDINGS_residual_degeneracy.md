# Finding: Conditions D and E are degenerate as currently configured

Date: 2026-09-27. Found while instrumenting the physics-delta fix, before the
re-run D/E seeds finished.

## What was measured

`scripts/check_residual_target.py` rolls out the real `AllegroPickupEnv` for 200
random steps and compares the true observation delta against the nominal
physics delta:

```
physics max abs error     7.594e-05
physics mean abs error    1.451e-06
true delta norm (mean)    25.3146
residual norm (mean)      0.0000
residual / true           0.0000%
```

The physics fix works. But it works *too* well: the residual the ensemble is
asked to learn is identically zero, because `compute_obs_delta` steps the same
`MjModel` with the same 10 substeps and the same action-to-ctrl mapping that
`AllegroPickupEnv.step` uses. The "nominal physics" model **is** the real
simulator, so there is nothing left to correct.

Two nominal calls on the same `(obs, action)` agree exactly, and replaying an
identical action sequence from an identical seed reproduces the state exactly.
The environment is deterministic and the nominal model is not an approximation
of it.

## Why this matters

The residual ensemble is trained to predict `true_delta - physics_delta`. With
that target identically zero it learns the zero function, and Conditions D and E
degenerate into Conditions A and B respectively, plus synthetic transitions
generated by an exact (but unlearned) simulator.

So the in-flight D and E runs cannot answer the question they were launched to
answer. They are not invalid the way the pre-fix runs were; they are
*uninformative*. Expect them to land near their A/B counterparts.

## The spec already anticipated this

`agents/05_RL_ALGORITHM_SPEC.md` lines 104-117 addresses exactly this case:

> To make the residual non-trivial (otherwise there is nothing to correct,
> since our "physics" model *is* the real simulator), Condition D is evaluated
> under **domain-randomized dynamics** at rollout time (randomized object
> mass/friction and actuator gains per episode), while the *nominal* physics
> model used inside $f_physics$ uses fixed default parameters.

The prescribed mechanism is domain randomization. Ranges are specified in
`agents/06_ROBOT_AND_SIMULATION_SPEC.md` section 4.

**It is not implemented.** `evaluation/robustness.py` is a stub whose own
docstring says "Phase 9 stub, no env mutation", and it sweeps by calling
`evaluate` repeatedly at different seeds rather than by perturbing model
parameters. There is no code anywhere in `src/` that randomizes object mass,
friction, or actuator gains.

## Options

1. **Implement domain randomization** (object mass/friction, actuator gains,
   per-episode, from seeded ranges) and re-run D/E. This is what the spec
   prescribes and the only option that makes the residual non-trivial. It is
   real Phase 8/9 work, not a patch.
2. **Report D and E honestly as degenerate.** State that with a deterministic
   simulator and an exact nominal model, residual augmentation has no signal to
   learn, so C is the only informative dynamics-augmentation condition. This is
   a legitimate finding and costs nothing.
3. **Redefine the nominal model** to be deliberately approximate (fewer
   substeps, simplified contact model, or missing parameters) so a residual
   exists. This deviates from the spec's framing and is worse than option 1.

Recommendation: let the current D/E runs finish (they cost nothing more, and
option 2 needs their numbers to demonstrate the degeneracy), implement domain
randomization, then re-run D/E. Do not report the D/E ordering as a result
about residual dynamics in the meantime.

## Related

The same degeneracy does not affect Condition C. Blackbox dynamics has no
physics prior, so it must learn the full delta from data and is unaffected.
